# 本体への観測接続案

確認日: 2026-10-17。本体3.13.698を対象としたコード点検と合成データ検査。今回、本体への接続は行っていない。

## 結論

最初に本体へ追加する範囲は、既存の文字形照合を読取項目別に示す開発表示とする。限定解析器への接続やprofileの自動認定は、この変更に含めない。診断結果・取得コマンド・保存形式を変えずに、どの項目の応答形式が未確認かを分かるようにする。

## 現在の経路と接続位置

| 本体の関数 | 確認した役割 | 接続方針 |
| --- | --- | --- |
| readObdDeveloperCoreScan | 4項目の原文ownerを作り、終了時にfinish、不完了時にinvalidate | 新しいowner・追加読取を作らない |
| runObdDeveloperRead | 正規化応答をretainObdDeveloperReadへ渡す。単回原文をtakeして集約ownerへappend | 診断結果を作る既存経路を維持 |
| readElmDeveloperCommandRecord | 送信前のsettingsBeforeReadと取得原文を返す | 後から得た設定で記録を補わない |
| createWebSerialReadoutCapture | 接続世代と順序を検証し、inspectで文字形照合を公開 | 閉じた原文記録の内部で項目別照合を作る |
| renderObdCoreRawReadoutStatus | inspectの結果を開発画面に表示 | 原文や診断コードを渡さず、項目名と理由だけ表示 |

## 所有権の制約

新しい表示からtakeを呼ばない。監査で、inspectを3回呼んでも4件が残り、takeは4件を一度だけ返してstatus=invalidated、reason=consumedになることを確認した。その後は既存の試験表示もunavailableになる。

試験用createParserConnectionReviewはownerを所有し、破棄時にinvalidateを呼ぶ。既存表示と共有する本体ownerへそのまま流用しない。本体では既存のownerが失効を管理し、表示側は観測結果だけを読む。

## 第一段階の具体的な差分案

- createWebSerialReadoutCaptureのreviewFormat内で、現在の照合理由をコマンド別に集める。形式はformatReview.readoutIssues内のcommandと凍結したissues配列を想定する。既存の全体issuesと件数は互換のため維持する。
- 対象は03・07・0A・0101のみ。現在の改行・終端、エコー、空白、文字形、フレーム文字形の有無の照合を使う。PCI・応答サービス・DTC件数などの内容解析は追加しない。
- 開発表示は取得前条件と文字形照合を別々に示す。「不一致なし」を診断成功や形式認定と表示しない。設定不足と原文の不一致を混同しない。
- 非完了・消費済み・世代失効・画面離脱後には項目別結果を残さない。inspectで原文を公開せず、takeの一回限りの挙動を変えない。
- retainObdDeveloperRead、一般decoder、buildBridgeSessionExportPayload、通常の診断結果表示は変更しない。

## 限定解析器へ接続する前に残ること

試験でprofileを指定して解析できたことは実機形式の認定ではない。ACK、対応通信番号、文字形が揃っていても、不正PCIや別サービス応答が文字形照合を通る反例がある。したがってparserAllowed=false、profile=null、profileVerified=falseを維持する。

将来の解析器接続は、どの機器・プロトコル・設定の根拠から形式を認定するかを別途決める必要がある。また、負応答・NO DATA・本文不正・ECU欠落を既存診断結果へどう反映するかを具体化する。現時点ではその契約を変更しない。

## 受入検査

1. 1項目だけに不一致を入れたとき、その項目だけに理由が出る。全体issuesは従来と同じ。
2. 設定不足、単独LF、空白、エコー、NO DATA、複数項目の異なる不一致を区別する。
3. 表示更新を繰り返しても原文を消費しない。失効後は表示を消し、古い通知で復活しない。
4. 模擬基本読取の送信順と回数、診断結果、保存JSONが変わらない。
5. Chromeの390/1280pxで開発表示を検査し、通常結果画面へ観測情報を混入させない。

今回の監査は54項目、関連検査は計302項目が合格。本体4資産が不変であることを含む。保存出力の追加プローブは、最上位へ注入した2つの私有フィールドが出力されないことの確認に限り、任意の入れ子データの非出力を証明するものではない。コード上の所有権・接続位置への確信度は高い。実機形式・実車適合は未確認。機材購入・実車接続はまだ不要。
