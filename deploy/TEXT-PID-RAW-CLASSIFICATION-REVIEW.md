# 状態系PIDの未換算分類案（本体未適用）

2026-10-10 / 基準: Web 3.13.651

## 現在の問題と今回の修正範囲

PID65/66/7B/7D/7E/85/88/8B/91は、バイト列を16進文字列にしただけでも `valueType: text` / `decoded: true` となる。実画面の要約に「換算済み9」と表示されるが、ビットの意味や各センサー値はまだ解釈していない。

3.13.651は応答長だけを固定し、内部41/42による切断・架空PID生成を防ぐ。既存の分類・保存ID・辞書・換算規則は変更しない。この分類問題を解決済みとは扱わない。

## 適用案

| 対象 | 現在 | 提案 |
| --- | --- | --- |
| 新規バイト応答 | text / decoded:true | raw_hex / decoded:false、既存の未換算注記 |
| 表示・集計 | 換算済み件数に入る | RAW・未換算を表示し、未換算件数へ入る |
| 値・ID・ECU・FF番号 | 元の文字列と識別情報 | 変更しない |
| 旧保存・外部の明示text値 | 既存の分類 | 自動再分類せずそのまま保持 |
| 既存の明示RAW値 | raw_hex / decoded:false | 変更しない |

例: `41 66 03 41 0D 28 42` は、`maf_sensor_status` の値 `03 41 0D 28 42` を維持したまま、解釈済みの文字列ではなく未換算RAWとして扱う。物理単位・センサー別数値・正常異常の判定は追加しない。

保存schema番号は変更しない案だが、新しく取得した記録の値分類と集計が変わる。旧記録は区別を維持するので、自動的に修復されたことにはならない。旧版3.13.651で新RAWを復元する互換性も確認対象とする。

## 表示名の別課題

PID66はMAFセンサーA/Bの値を含むが現行名はMAFセンサー状態、7BはDPFバンク2圧力群だがDPF状態、91はECU情報だが車両情報となっている。前回確認した87のA/B、8Fのバンク1/2、89のAECD#11〜15と併せ、保存IDを維持した表示改善を検討する。この分類案では辞書や旧記録の名称を一括変更しない。

根拠: [SAE J1979-DA OCT2011原文ミラー](https://www.e90post.com/forums/attachment.php?attachmentid=1509324&d=1476497126)、Tables B81/B82/B103/B105/B106/B112/B115/B118/124。PID88はA〜Mの13バイト、91はA〜Eの5バイトを確認。PID66は序文の例示と本文表に不一致があり、B82の5バイト（A、B/C、D/E）を採用している。最新規格や実車適合の証明ではない。

## 検証と適用境界

`node deploy/scripts/validate-text-pid-raw-proposal.js` はメモリー上だけで対象9PIDを未換算化し、新旧保存・旧リーダー・集計・値と識別情報・送信禁止を検証する。さらに既存の複合PID全検証を隔離案へ実行する。261項目の契約・新旧保存検査と複合PID14,168項目が合格した。通常本体・配布物を変えず、実車通信もしない。通常の全体回帰へはまだ組み込まない。

本体適用前に、新規記録を未換算RAWへ分類する変更の確認を受ける。適用時は旧保存の保持、実JSON取込からのライブ/FF表示・集計・保存復元、全体検証・配布検証を再実施する。
