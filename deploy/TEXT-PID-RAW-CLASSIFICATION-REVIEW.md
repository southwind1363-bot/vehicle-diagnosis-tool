# 状態系PIDの未換算分類（承認済み・本体適用）

2026-10-10 / 旧版: Web 3.13.651 / 適用版: Web 3.13.652

ユーザーの「承認します」を受けて、以下の分類変更を本体へ適用した。

## 旧版の問題と修正範囲

PID65/66/7B/7D/7E/85/88/8B/91は、バイト列を16進文字列にしただけでも `valueType: text` / `decoded: true` となっていた。実画面の要約に「変換済み9」と表示されるが、ビットの意味や各センサー値はまだ解釈していない。

3.13.651では応答長を固定した。3.13.652では新規バイト応答を未換算RAWへ分類する。既存の保存ID・辞書・保存schema番号を維持し、数値換算は追加しない。

## 承認された変更

| 対象 | 3.13.651 | 3.13.652 |
| --- | --- | --- |
| 新規バイト応答 | text / decoded:true | raw_hex / decoded:false、既存の未換算注記 |
| 表示・集計 | 変換済み件数に入る | RAW・未換算を表示し、未変換件数へ入る |
| 値・ID・ECU・FF番号 | 元の文字列と識別情報 | 変更しない |
| 旧保存・外部の明示text値 | 既存の分類 | 自動再分類せずそのまま保持 |
| 既存の明示RAW値 | raw_hex / decoded:false | 変更しない |

例: `41 66 03 41 0D 28 42` は、`maf_sensor_status` の値 `03 41 0D 28 42` を維持したまま、解釈済みの文字列ではなく未換算RAWとして扱う。物理単位・センサー別数値・正常異常の判定は追加しない。

旧記録は区別を維持し、自動的に修復されたことにはならない。旧版3.13.651で新RAWを復元する互換性も確認した。

## 表示名の別課題

PID66はMAFセンサーA/Bの値を含むが現行名はMAFセンサー状態、7BはDPFバンク2圧力群だがDPF状態、91はECU情報だが車両情報となっている。前回確認した87のA/B、8Fのバンク1/2、89のAECD#11〜15と併せ、保存IDを維持した表示改善を検討する。今回の分類変更では辞書や旧記録の名称を一括変更しない。

根拠: [SAE J1979-DA OCT2011原文ミラー](https://www.e90post.com/forums/attachment.php?attachmentid=1509324&d=1476497126)、Tables B81/B82/B103/B105/B106/B112/B115/B118/124。PID88はA〜Mの13バイト、91はA〜Eの5バイトを確認。PID66は序文の例示と本文表に不一致があり、B82の5バイト（A、B/C、D/E）を採用している。最新規格や実車適合の証明ではない。

## 検証と適用範囲

承認前の隔離案は261項目と複合PID14,168項目で検証した。承認後は本体を直接検査する回帰へ昇格し、`node deploy/scripts/validate-text-pid-raw-proposal.js` の225項目と複合PID14,168項目が合格。ファイル名は既存参照のため維持する。全体OBD検証にも組み込んだ。

3.13.651の実デコーダから取得した文字列記録をfixtureとして保持し、新旧の値・ID・分類・ECU・FF番号と保存往復を検証した。別途、旧版リーダーによる新RAWの復元と、短い16進文字列・一般文字列・0文字列の保持を90記録で確認。

実JSON取込→ライブ/FF画面→保存復元で、新RAW9項目は「未変換9」、旧文字列9項目は「変換済み9」と表示する。390/1280px・明暗を確認。既存RAW21項目の表示も維持。旧記録に新しい意味を付けず、車両送信・数値換算・実機適合の追加は行わない。
