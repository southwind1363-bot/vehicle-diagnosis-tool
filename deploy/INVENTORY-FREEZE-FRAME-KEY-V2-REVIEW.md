# フリーズフレーム取得集計・保存比較キーの移行案

2026-10-11 / 本体3.13.662 / 本体への移行は未適用

## 確認した問題

同じengine_speed・記録番号0・ECU 7E8・1200 rpmでも、経路A|BとA Bの測定行は別物である。現行本体では元の2行を保持する一方、freezeFrameValueKeysが同一になり、freezeFrameValueCountは1になる。片方の経路だけの記録をもう片方と比較すると、比較可能かつキー変化なしになる。

バス・チャネル・ゲートウェイ経路の縦棒/空白、未指定/文字列ハイフンを、両順序の計12ケースで確認した。未指定の試験では他の経路欄を残し、経路情報全体が未指定の場合とは区別した。

測定値キーだけでなく、トリガーDTCキー、UDSスナップショット/保存データ記録キー、取得済みECU経路キーにも同じ衝突を確認した。UDSは別経路の計4記録が2キーになる。これは模擬入力の結果であり、実車通信の確認ではない。

## 具体的な変更案

共通のfreezeFrameKeyVersion / freeze_frame_key_versionを2とし、以下の派生キー群を一緒に移行する。schema_versionのcore_readout_inventory_v1と元の測定行は維持する。

| 対象 | 接頭辞 | JSON配列の要素 |
| --- | --- | --- |
| 測定値 | ff_value_v2: | id, frameNumber, sourceEcu, unit, reportedValue, bus, channel, route |
| 起点DTC | ff_trigger_v2: | code, subcode, codeFormat, reportedStatus, frameNumber, sourceEcu, bus, channel, route |
| UDS記録 | ff_uds_record_v2: | kind, code, recordType, statusByte, memory, recordNumber, identifierCount, sourceEcu, bus, channel, route |
| ECU経路 | ff_scope_v2: | sourceEcu, bus, channel, route |

経路は既存の経路正規化・全半角/大小文字の整合を使い、未指定はJSONのnull、文字列ハイフンは文字列として区別する。縦棒はJSONのUnicodeエスケープで保存し、旧区切り解析が新キーを誤読しないようにする。経路以外の既存フィールドの正規化・RAW分類・換算は変更しない。

取得済み/未解決ECU経路と部分取得のキー選別、camel/snake alias、JSON取込/保存、比較結果表示を同時に変更する。測定値だけ先に移行して他のFF比較へ旧経路キーを流さない。

## 保存記録の互換性

1. v2同士は既存の取得状態条件を維持し、経路の異なるキーを別項目として扱う。FFの比較は追加/削除キーの比較であり、この移行で新しい数値差分や故障判定は追加しない。
2. 旧形式とv2、矛盾した版・alias、不正なキーは比較不可にする。旧経路付き形式同士も安全な同一経路とみなさない。経路未指定の旧形式同士の既存比較は維持する。
3. 比較不可のときは追加/削除を空配列にするだけで済ませず、画面に比較不可の理由を示す。「変化なし」「差分なし」と結論しない。
4. 元の測定行と経路がある旧ファイルは読み込み、新しい現在集計を生成する。ただし保存されていた旧集計との比較は不可とする。失われた経路を推測して復元しない。
5. 元の測定値、RAW、トリガー、UDS記録は削除・書換えしない。ECUへの送信や消去機能は追加しない。
