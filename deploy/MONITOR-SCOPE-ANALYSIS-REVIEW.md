# ECU・通信経路別のライブ値分析・適用記録（3.13.675）

2026-10-11 / 本体3.13.674・6bde067e / 確認後3.13.675へ適用

## 再現した問題

1. analyzeMonitorValuesが項目IDだけで最後の値を選ぶ。ECU 7E8の9 V、7E9の14 Vの順では低電圧注意が消え、逆順では出る。同じECU番号でもバス・チャンネル・ゲートウェイ経路の違いを無視する。
2. 別ECUの短期補正10%と長期補正10%を合計20%として注意表示する。別経路や、経路未記録と明記済みの組合せでも発生する。
3. mergeDiagnosticInputsも項目IDだけで統合するため、分析前に別ECUの測定値が落ちる。分析関数だけの変更では解消しない。
4. ECU未記録の2行と7E8の1行を正規化すると、記録全体のsourceEcuが7E8になる。再正規化すると未記録行にも7E8が補われ、初回には保留した相関が後から生成される。

合成入力と旧版の分析結果19ケースはscripts/fixtures/monitor-scope-legacy-3.13.674.jsonに固定した。実車記録ではない。

## 適用した差分

- ECU文字列（前後空白除去・大文字化）と、既存正規化を通したバス・チャンネル・ゲートウェイ経路の組をJSON配列で識別する。区切り文字を含む名前や未記録値を混同しない。CANアドレスの部分抽出で異なる名前を推定統合しない。
- 同じ取得元の範囲で既存の分析を行う。分析文のdetailに対象ECUと各経路、未記録の項目を表示する。数値閾値・RAW除外条件は維持する。グループごとの既存6件上限は維持し、全グループ合計への6件打切りは設けない。
- 複数の取得元が混在する記録では、ECU未記録の値を相関計算せず、その理由を表示する。単独値で判定できる電圧注意は残す。分析へ届いたECU別名の矛盾・不正値、経路矛盾のある行は除外件数を表示する。
- 統合APIも項目IDと取得元の組で値を保持する。同じ取得元・同じ項目の既存優先順位は維持する。既知ECUと混在する未記録行や矛盾行は、同じ取得元だと仮定して統合しない。
- 全行のECUが記録されていて1種類の場合だけ、行から記録全体のECUを補う。未記録行が混在する場合はsourceEcu/source_ecuをnull、livePidScope/live_pid_scopeをunknownとする。入力で明示された記録全体のECUの扱いは変更しない。
- 保存済み分析文は3.13.674の原文保持を継続する。新しい再計算文は出所を含む文章になるため、旧文と併存する場合がある。記録内分析文を現在の車両状態として扱わない。

## 保存内容への影響と範囲

schema名・フィールド名は追加しないが、統合後のmonitorValues件数、集計値、monitorInsights文章・件数が変わる。未記録混在時は上記の記録全体ECU・scopeも変わる。過去に失われた値や、既に補われたECU番号の元の状態は復元できない。

全行が出所未記録の従来入力は既存分析を維持する。同一取得元内の重複選択も維持するため、分析関数の「最後の行」と統合APIの「数値等を優先する採点」は引き続き異なる。同じECU・経路でも、同時測定や同じ車両を証明するものではない。

ECUのcamel/snake等の別名が矛盾する入力について、上流のnormalizeBridgePidValueは既に一方を選択する。この案は失われた矛盾を復元しない。経路矛盾行も上流で除外される場合がある。矛盾検出の試験は分析へ直接届いた行を対象とし、JSON取込の矛盾保持を修正したとは扱わない。この入力契約は次の点検対象とする。

車両通信・書込み権限、実ドライバー、VCIの試験は含まない。3.13.675へ適用。配布・公開の検証結果は下記に追記する。PC・タブレット購入は不要。
