# 対応PID・Mode06の経路保持と集計キー移行案

2026-10-11 / 本体3.13.665 / 承認済みの変更を適用

## 本体関数で確認した問題

`scripts/validate-inventory-pid-mode06-key-review.js` の265項目・26ケースで再現した。固定入力を使用し、車両やVCIには接続していない。

- 対応PID: バス・チャネル・ゲートウェイ経路のA|BとA B、未指定と文字列ハイフンが同じキーになる。通常取込で2つのECU観測を保持していても集計は1キーとなり、経路変更を変化なしと判定する。両順序12ケース。
- Mode06: 状態・数値キーは経路を含まない。上記12ケースとCAN-PT/CAN-BODYの両順序2ケースで衝突する。数値行2件は残るが、通常正規化で試験行と子ECU記録の経路フィールドが失われる。保存復元も失われた経路を回復しない。
- Mode06の部分取得: 親状態をunparsedとした記録で、以前はCAN-PTのみ取得済み、現在はCAN-BODYのみ取得済みでも、同じ7E8として数値変更を比較する。
- Mode06の行選択: CAN-PTが取得済み、CAN-BODYが未解析のとき、直接行にあるCAN-BODYの値9を、7E8が一致するだけで取得済みキーへ入れる例を確認した。CAN-PT子記録の値は1。
- Mode06の欠落した限界値: 元の行ではmin/maxがnullのままだが、集計のNumber(null)で0に変わり、明示された0/0と同じ数値キーになる。

親状態を省略した子記録のみの入力は別の取込経路でblockedとなる場合があるため、部分比較の再現は親状態を明示した入力に限定する。すべての入力が誤比較されるという主張ではない。

## 適用した変更

### 1. Mode06の経路保持・行選択

通常正規化、ブリッジ取込、JSON取込の試験行・子ECU記録へ既存のnetworkBus/networkChannel/gatewayRouteとsnake alias、提供有無・矛盾の情報を保持する。親から子への継承も既存の経路規則に従い、異なる指定を上書きしない。

取得済み行の採用はECU番号だけでなく経路の一致で決める。同じECUに複数経路がある場合、経路未指定の直接行を特定経路へ推測で割り当てない。矛盾・未解析の経路を取得済みの代用にせず、全体が取得済みになる条件も子記録の取得状態と整合させる。通常詳細画面でも経路を表示し、検索で区別できるようにする。

数値、TID/CID、限界値、pass/fail/unknownの意味を維持する。意味や単位を車種別の整備書なしに推定しない。正しい経路の取得済み行だけから件数を集計し、誤採用された行が除外される場合には表示件数も変わる。

### 2. 独立したv2集計キー

core_readout_inventory_v1を維持し、supportedPidKeyVersion / supported_pid_key_versionとonboardMonitorKeyVersion / onboard_monitor_key_versionを独立して2にする。JSON配列の識別子とし、縦棒をUnicodeエスケープで保持する。

| キー | JSON配列 |
| --- | --- |
| supported_pid_v2 | [pid, sourceEcu, bus, channel, route] |
| supported_pid_scope_v2 | [sourceEcu, bus, channel, route] |
| mode06_test_v2 | [testId, componentId, sourceEcu, status, bus, channel, route] |
| mode06_value_v2 | [testId, componentId, sourceEcu, value, min, max, bus, channel, route] |
| mode06_scope_v2 | [sourceEcu, bus, channel, route] |

経路は既存のNFKC・小文字化と上限検査を使い、未指定nullと文字列ハイフンを区別する。数値キーのvalueは有限数、欠落min/maxはnull、明示0は数値0とする。正規化後にも重複を除去する。

完全取得では経路別の追加/削除として比較し、部分取得ではECU番号と経路が共通する取得済み範囲だけ比較する。取得済み・未解決の経路キーを保存し、旧版や不正キーで比較できない場合は数値・不合格件数等の差分も未判定とする。元の保存件数自体は保持する。Readiness・ECU情報・FF・ライブの版管理へ影響させない。

## 旧記録・保存復元の境界

- 古いファイルの読込は維持する。Mode06の旧正規化で消えた経路は復元できず、ECU番号から経路を補わない。
- 対応PIDの旧経路なし形式同士は維持し、旧経路付き同士・旧版/v2混在は詳細比較不可とする。
- Mode06の旧形式は経路欠落を判別できないため、旧形式同士を含め詳細比較不可とする。新形式の未指定経路同士は未指定の範囲として扱い、指定済み経路の代わりにはしない。
- 版・camel/snake aliasの矛盾、不正なキー、未知状態の破壊を防ぎ、不正判定を保存復元で消さない。比較不可を通常画面へ表示し、空の追加/削除配列を差分なしと扱わない。

## 適用後の受入検査

旧出力を固定fixtureへ保存し、今回の再現検査を修正後の期待値へ切り替える。直接行/子記録/ブリッジ/通常JSON、同一・異なる・未指定・矛盾経路、完全/部分/失敗、0/null/未知状態、旧版互換境界、alias不正、保存復元、通常詳細画面を検証する。全体OBD・ブリッジ・オフライン・端末・配布ZIPと公開HTTP照合を完了する。

承認後、上記の変更を3.13.665へ適用した。旧3.13.664の出力を scripts/fixtures/inventory-pid-mode06-3.13.664.json に固定し、再現検査を351項目の回帰検査へ変更した。親子の経路矛盾、同一経路の取得状態矛盾、不合格件数差分の未判定、正規化後の重複除去、通常画面の経路検索も含む。

直接行が存在する場合は従来どおり直接行を優先し、未解析経路の直接行を除外した後で子の値へ置き換えない。子ECU記録は保持する。明細がなく元の集計値だけが残る記録は、その集計を保持して「検査明細なし」と表示する。実車通信は行っていない。
