# ライブ推移の経路識別修正案（本体未適用）

2026-10-10 / 対象 Web 3.13.657

## 再現した問題

比較集計の経路キーは、値内の `|` を空白へ置換し、未指定欄を `-` で表現する。このため正規化後も異なる経路が同じキーになり、同じPID・ECU・単位の値を比較する場合がある。現行本体の関数で再現した。実車で発生したと確認したものではない。

| 入力例 | 現行の比較 | 修正案 |
| --- | --- | --- |
| バス `CAN|A` と `CAN A`、0→100 rpm | 比較1件、差分+100 | 比較0件、経路不一致1件、差分なし |
| バスCAN、チャネル `-` と未指定 | 比較1件 | 比較0件、経路不一致1件 |
| チャネル1、バス `-` と未指定 | 比較1件 | 比較0件、経路不一致1件 |
| バスCAN、経路 `-` と未指定 | 比較1件 | 比較0件、経路不一致1件 |
| チャネル／経路 `a|b` と `a b` | 比較1件 | 比較0件、経路不一致1件 |
| 同じ経路、通常値、0 | 既存の比較 | 維持 |

3.13.657のグラフはこれらを別系列にする。修正案は比較集計でも区別する。`comparisonAvailable` は時刻・取得条件の比較可否を示す既存のフラグとして維持し、数値比較件数とは区別する。

## 提案する実装

`buildLivePidTimelineSummary` 内の `monitorComparisonKey` だけを変更する。既存の `normalizeReadoutNetworkScope` で矛盾・表記揺れを処理し、欠落値をnullのまま保った配列をJSON化して比較キーに使う。入力値の `|` や `-` を区切り・欠落記号へ変換しない。

```js
const monitorComparisonKey = (item) => {
  const scope = normalizeReadoutNetworkScope(item);
  if (scope.conflict) return null;
  return JSON.stringify([monitorComparisonBaseKey(item),
    ...[scope.networkBus, scope.networkChannel, scope.gatewayRoute]
      .map(value => value === null ? null : value.normalize("NFKC").toLowerCase())]);
};
```

保存schema、正規化、サンプルの値・分類・経路・時刻、車両送信や実行許可は変更しない。旧記録から再計算する比較件数・差分・経路不一致件数は変わることがある。共通の `getReadoutNetworkScopeKey` は他の結合・照合にも使われるため、今回変更しない。それらの経路衝突対策は別途影響調査が必要であり、今回解決済みとはしない。

## 検証

`node deploy/scripts/validate-timeline-scope-key-proposal.js`

本体を読み込むVMと、上記1関数内のみを変更したVMを比較。150項目合格。

- 6種類の衝突を前後両方向で再現し、修正案の比較0件・経路不一致1件を確認。
- 正規化済み入力でも分離。JSON取込・再保存で保存サンプルを保持。
- 同一経路、全半角・大文字小文字・前後空白・別名フィールドの等価性を維持。
- 経路矛盾、異なるECU・単位・取得条件・同一時刻、RAW/textの既存除外を維持。
- 固定された旧版fixture 11ケースの比較集計は現行と一致。
- 本体ファイルは書き換えず、テスト用VM内だけで変更。実車・VCI・ブラウザーの試験ではない。

本体適用時には、この隔離試験を本体回帰試験へ切替え、画面の集計表示・全体OBD・配布検証を実施する。
