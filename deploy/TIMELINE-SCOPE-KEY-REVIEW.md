# ライブ推移の経路識別修正（承認済み・本体適用）

2026-10-10 / 旧版 Web 3.13.657 / 適用版 Web 3.13.658

## 再現した問題

比較集計の経路キーは、値内の `|` を空白へ置換し、未指定欄を `-` で表現する。このため正規化後も異なる経路が同じキーになり、同じPID・ECU・単位の値を比較する場合がある。修正前3.13.657の関数で再現した。実車で発生したと確認したものではない。

| 入力例 | 3.13.657の比較 | 3.13.658 |
| --- | --- | --- |
| バス `CAN|A` と `CAN A`、0→100 rpm | 比較1件、差分+100 | 比較0件、経路不一致1件、差分なし |
| バスCAN、チャネル `-` と未指定 | 比較1件 | 比較0件、経路不一致1件 |
| チャネル1、バス `-` と未指定 | 比較1件 | 比較0件、経路不一致1件 |
| バスCAN、経路 `-` と未指定 | 比較1件 | 比較0件、経路不一致1件 |
| チャネル／経路 `a|b` と `a b` | 比較1件 | 比較0件、経路不一致1件 |
| 同じ経路、通常値、0 | 既存の比較 | 維持 |

3.13.657のグラフはこれらを別系列にする。3.13.658は比較集計でも区別する。`comparisonAvailable` は時刻・取得条件の比較可否を示す既存のフラグとして維持し、数値比較件数とは区別する。

## 適用した実装

`buildLivePidTimelineSummary` 内の `monitorComparisonKey` だけを変更した。既存の `normalizeReadoutNetworkScope` で矛盾・表記揺れを処理し、欠落値をnullのまま保った配列をJSON化して比較キーに使う。入力値の `|` や `-` を区切り・欠落記号へ変換しない。

```js
const monitorComparisonKey = (item) => {
  const scope = normalizeReadoutNetworkScope(item);
  if (scope.conflict) return null;
  return JSON.stringify([monitorComparisonBaseKey(item),
    ...[scope.networkBus, scope.networkChannel, scope.gatewayRoute]
      .map(value => value === null ? null : value.normalize("NFKC").toLowerCase())]);
};
```

保存schema、正規化、サンプルの値・分類・経路・時刻、車両送信や実行許可は変更しない。旧記録から再計算する比較件数・差分・経路不一致件数は変わることがある。共通の `getReadoutNetworkScopeKey` は他の結合・照合にも使われるため、今回変更していない。それらの経路衝突対策は別途影響調査が必要であり、今回解決済みとはしない。
