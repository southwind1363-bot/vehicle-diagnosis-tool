# ECU番号の同義項目が矛盾するJSONの取込停止（3.13.676）

2026-10-11 / 調査対象3.13.675・ed4087e7 / ユーザー確認後、3.13.676へ適用

## 再現した問題

同じ測定行にsourceEcu: "7E8"とsource_ecu: "7E9"があると、normalizeBridgePidValueが後者を選び、両方を7E9へ揃える。直接の分析では除外される矛盾が、JSON取込・正規化の後には確認できなくなる。

矛盾する短期燃料補正10%と、7E9の長期補正10%を組み合わせる入力では、JSON取込後に合計20%の注意文が生成された。スナップショットの見出し・子ECUの見出しでも、片方を選択する経路を再現した。

旧版の結果のSHA256、選択後の値・ECUと分析文をscripts/fixtures/ecu-alias-import-legacy-3.13.675.jsonへ固定した。時刻は固定して採取。合成入力であり、実車証拠ではない。

## 適用した仕様

JSONの解析後、正規化・native archive処理・他形式への分岐より前に、同一オブジェクト内のsourceEcuとsource_ecuを検査する。

1. 両項目がnull/欠落以外の値を持つ場合に比較する。文字列の前後空白と大文字小文字の違いは許容する。
2. 両方に値があり、空文字・文字列以外・比較後の不一致があれば、ファイル全体を拒否する。一致する方を推定で選択したり、正常な行だけを部分取込したりしない。
3. 検査はJSON全体を反復走査する。ライブ値・FF・子ECU・入れ子のsession/reportだけでなく、メタデータや未使用の項目内の同義項目にも適用する。同じオブジェクト内の2項目だけを比べ、別オブジェクトに属する親子・複数ECUの値同士は比較しない。
4. 拒否結果はaccepted:false / ok:false / blocked:trueと、source_ecu_alias_conflictのエラーを返す。nullでは返さず、CSV・通常テキスト解析へのフォールバックを防ぐ。車両送信・書込みはfalse。
5. UIは理由を日本語で表示する画面へ移動し、現在の読取セッションと表示済みの結果を保持する。誤ったファイルで上書きしない。取込失敗後に正常なJSONを開ける。

表示文:

> 同じ箇所に記録された2つのECU番号が一致しないか、形式が不正なため、このJSONは取り込めません。元ファイルの取得元を確認してください。現在の読取結果は保持しています。

## 変更する契約と限界

- 従来取り込めた矛盾JSONが取込不可になる。未使用のメタデータ内の矛盾も拒否対象とする保守的な方針であり、元ファイルの確認・修正が必要になる場合がある。
- 片方だけが記録されている場合、片方または両方がnullの場合は、既存の取込処理を維持する。単独項目の型・長さの検査を新しく強化する案ではない。
- 保存schema・正常な保存値・分析閾値は変えない。元ファイルを書き換えず、矛盾の修正値を推定しない。出力のexported_atは通常どおり出力時刻になる。
- 対象はbuildDiagnosticScanSessionFromJsonを通るJSON入力。この関数を通らない直接のブリッジ正規化・統合には適用されない。既に片方へ揃えられた旧記録から、元の矛盾を復元することはできない。
- ecu/address/module等の別名との矛盾、親と子の明示ECUが異なる場合の扱い、直接ブリッジ入力の矛盾保持は残る課題。今回の検査を、全取得元の真正性やECU適合を証明するものとは扱わない。
