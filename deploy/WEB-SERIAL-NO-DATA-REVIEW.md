# 保留・永久DTCのNO DATA集計修正案

確認日: 2026-10-13。本体3.13.690への適用前。対象はWeb Serialの07（保留DTC）と0A（永久DTC）。

## 再現した不一致

本体の模擬基本読取で07または0Aに `NO DATA` が返ると、DTC取得状態は未取得のままだが、読取実行集計では空応答を取得した扱いになり、当該読取を完了に数える。NO DATA件数そのものは1のまま残る。診断で故障なしを確定したという再現ではなく、取得状態と実行集計の不一致である。

原因は `isWebSerialExpectedEmptyResponse` が07と0AのNO DATAを例外的な空取得に分類し、`buildWebSerialReadoutOutcome` がその件数を完了判定に加えること。DTC応答overrideの生成も同じ関数を使う。

## 適用する場合の変更

| 応答・条件 | 現行 | 修正案 |
| --- | --- | --- |
| 07/0AのNO DATA | 空取得件数に含め、実行集計は完了になり得る | 空取得件数から除外し、未完了または一部取得に数える |
| 07/0Aの正常な0件応答（47/4A） | 取得済み・コード0件 | 同じ |
| NO DATA件数 | 記録する | 同じ |
| 03のNO DATA | 未取得・未完了 | 同じ |
| 0202/06/0900の既存空応答例外 | 既存分類 | 今回は対象外 |

変更案は例外一覧から07と0Aだけを外す。保存schema、既存保存記録の書換え、送信コマンド、再送、消去権限の追加は行わない。今回から取得する読取結果の集計・生成される応答overrideが変わるため、本体適用前に判断する。

## 隔離検証

`scripts/web-serial-no-data-proposal.js` が本体ソースをメモリ内だけで変換する。`scripts/validate-web-serial-no-data-proposal.js` は既存結合試験の模擬portと本体関数を利用する。本体資産と既存検査は変更しない。

正常取得→NO DATA→正常復帰を、03/07/0A/0101ごとに同じ接続で試す。各読取前に明示初期化し、旧設定を再利用しない。旧故障コードの除去、未取得状態、NO DATA件数、復帰後の新DTC3件、JSON保存復元、過去オブジェクト不変、旧原文集約の失効、接続の再選択なし、終了時の解放を検証する。47/4Aの正常0件と対象外コマンドの既存分類も新旧双方で照合する。

結果: 現行不一致の再現56項目、修正案の連続読取・保存復帰311項目、変更対象外の対照試験は新旧各42項目（合計451項目）が合格。変換先の契約が変わっていた場合の拒否も確認。

実行: `node scripts/validate-web-serial-no-data-proposal.js`。実機やドライバーへは接続しない。集約原文のparser接続や実車適合確認は引き続き未完了。

## 適用判断

読取結果の完了条件に関わる変更なので、この案の本体適用は確認後とする。現在の公開本体は3.13.690のまま。
