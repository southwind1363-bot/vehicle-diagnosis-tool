# 取得範囲の共通経路照合 修正案

2026-10-11 / 対象本体3.13.665 / 本体への適用前

## 再現と試作

node deploy/scripts/validate-readout-scope-identity-review.js で304項目・12経路ケースが合格した。実際の本体を読み込み、現行版と、共通内部キー関数だけを差し替えたVM内試作を比較する。本体・バージョン・配布ZIPは変更していない。車両・VCIには接続しない。

バス・チャネル・ゲートウェイの各フィールドで「A|B」と「A B」、「未指定」と文字列「-」を両順序で確認した。他の2フィールドは指定済みである。現行の getReadoutNetworkScopeKey は縦棒を空白へ置換し、未指定をハイフンへ変換するため、別経路が同じ識別子となる。

| 通常取込・集計の固定入力 | 現行3.13.665 | VM内試作 |
| --- | --- | --- |
| 同じ7E8の一方が取得済み、別経路が未解析。直接行には未解析側のECU情報のみ | 未解析側の値を採用 | 採用しない |
| 上記のECU情報集計 | 経路群1、取得済み0、未解析1 | 経路群2、取得済み1、未解析1 |
| 同じ7E8・同じPIDの2経路から応答概要を作成 | 応答行1 | 応答行2 |

JSONへの出力・再取込でも両版のECU情報選択と経路群数を確認した。全体取得済みには昇格せず、送信・車両操作の許可はfalseのままである。これは固定入力による反例であり、全記録で発生するという意味ではない。

## 提案する変更

共通内部キー getReadoutNetworkScopeKey を、既存の getDtcReadoutNetworkScopeIdentity が返すJSON配列識別子へ統一する。NFKC・小文字化・既存の入力長制限は維持する。未指定nullと文字列ハイフン、縦棒と空白を区別する。矛盾はnull、完全未指定は空文字のままとする。

readoutNetworkScopeMatches の「期待経路が未指定なら範囲を限定しない」という既存仕様は、この変更で拡張も縮小もしない。camel/snake alias矛盾の拒否、全角・大小文字の同一視も検証した。

この内部キーはECU応答の照合・集約、DTC/FF/Readiness/ECU情報の行選択、FFの並び順、以前の閾値証拠の照合にも使われる。本体適用時にはそれぞれの回帰検査が必要。今回304項目はその全経路の検証完了を意味しない。

## 記録への影響と適用条件

保存フィールドや既存の集計キーv2を追加変更する案ではない。ただし再取込時の診断結果は変わる。以前混同した経路の件数が分離し、未解析経路の情報が取得済み明細から除かれる場合がある。過去に失われた行は復元できない。元ファイルを自動で書き換えず、推定で値を補わない。

前回の承認対象は対応PID・Mode06の経路保持と集計キー移行だった。今回は共通の取得範囲判定とECU集計の診断結果に及ぶため、この範囲を確認してから本体へ適用する。

承認後は、固定した旧出力との比較、全呼出し先の不一致/未指定/矛盾経路、既存キーv2、通常画面・保存復元を検証する。必要な全体検査、配布ZIP、公開HTTP照合を完了する。実車通信やドライバー実行は追加しない。
