# R2 monitor前後記録の確認画面案

2026-10-05。状態: 設計済み・画面未実装。対象は固定模擬データを使う開発用確認画面。実車向け比較画面の公開条件を満たしたものではない。

## 目的と既存実装

前後の報告状態と対応付けを保留した理由を、ECUごとに読めるようにする。消去成功、故障解消、改善・悪化、readiness全体の完了は判定しない。

根拠は [最小証拠設計](R2-MINIMAL-COMPARISON-EVIDENCE-DESIGN.md)、[Node専用handle](scripts/fixtures/dtc-clear-scoped-before-readout.js)、[scope](scripts/fixtures/dtc-clear-readout-scope.js)、[固定プレビュー](scripts/preview-dtc-clear-monitor-pairs.js)。Node fixtureはfs/vmを使うため、ブラウザー本体へ直接importしない。現在のプレビューは取得直後にhandleを破棄しており、返した文字列は有効なhandleの代用品にならない。

## 最初に作る画面の範囲

次の実装単位は、通常アプリと独立した開発用の静的HTML見本。Nodeで固定サンプルの出力を生成し、HTMLエスケープした表示用文章だけを埋め込む。出力時点の見本であることを常時示し、現在の有効性を表す表示は付けない。任意JSON、ファイル選択、実車セッション、既存の保存記録を入力する入口は作らない。

通信・認証・保存・service worker・外部資材を必要とせず、ネットワーク停止状態でも開ける形にする。通常メニューや配布ZIPへの追加は別の判断とする。見本の作成を、以下の動的な失効処理の実装・合格とは扱わない。

## 画面の構成

| 順序 | 表示内容 | 表示規則 |
| --- | --- | --- |
| 1 | 「模擬の前後記録」 | 「実車の読取結果ではありません」を常時表示 |
| 2 | 取得元と記録の扱い | 「固定サンプル・出力時点の見本」「実車比較は未確認」「車両送信なし」。固定時刻を実際の取得日時として表示しない |
| 3 | 利用上の意味 | 状態変化は消去成功・故障解消の証明ではない。実車の判断には対象整備書の確認が必要 |
| 4 | ECUごとの記録 | ECU ID、基本/非連続monitor、前/後の報告された点火方式を示す |
| 5 | monitorごとの記録 | monitor ID、前の状態、後の状態、相違または保留理由。欠落は「報告なし」で0や完了へ補正しない |

幅390pxでは前後を縦に並べても「前」「後」の見出しを残す。長いmonitor IDは折り返し、ページ全体の横スクロールを発生させない。状態を色だけで区別せず文字で表示する。保留理由と模擬表示は折りたたまない。静的見本には動作しない消去・再読取・承認ボタンを置かない。

表示例: `7E8 / 基本monitor / misfire` の下に `前: 完了`、`後: 未完了`、`報告状態が変化`。7E9では値が同じでも `対応付け保留: 点火方式の報告が異なる` を示す。ECU間で件数や完了率を合算しない。

## 将来、所有handleへ接続する場合の状態と寿命

以下は未実装の要件。静的見本には適用済みと表示しない。ブラウザー用の所有権管理と失効通知の経路は別途設計・レビューし、Node fixtureを移植するだけで済ませない。

| 状態 | 画面 | 次の操作 |
| --- | --- | --- |
| 未取得 | 「前後記録がありません」・monitor行なし | 許可された取得元で明示取得 |
| 取得中 | 「前後記録を確認中」・旧monitor行なし | 重複取得を開始しない |
| 有効な模擬記録 | 取得元と模擬限定表示を付けて前後を表示 | 表示更新前に同じ所有handle/contextを検査 |
| 失効・破棄・参照不一致 | 「記録の確認条件が変わりました」・旧monitor行なし | 新しい条件で明示取得。旧handleを復活させない |
| 取得拒否・例外 | 「前後記録を確認できません」・旧monitor行なし | 固定案内を表示。自動再試行しない |

画面を閉じる、ロック、対象/接続の変更、元記録の更新、モード/段階移動で画面の世代番号を進め、所有handleを破棄し、scopeを失効させる。共有される通常の診断記録・保存記録は削除しない。通知で行を即時に除去する処理と、取得時の再検査の両方が必要。再描画時の検査だけでは、失効後に描画済み行が残る問題を解決しない。

遅れて返った結果は画面の世代・handle参照・contextがすべて開始時と一致する場合だけ採用する。閉じて開き直した画面への旧結果の流入も拒否する。生の例外、token、transcript、保存JSONはDOMやログへ出さない。未知の理由は一般的な確認不能として扱う。

取得済み文章やスクリーンショットは回収できない。消去や比較の許可は表示文字列から復元しない。ダウンロード、永続保存、クリップボード操作の追加は保存・プライバシー・互換性の別設計対象とする。

## 受入条件と段階

| 段階 | 確認内容 | 合格によって主張できること |
| --- | --- | --- |
| 静的見本 | 7E8変化/7E9方式変更/7EA不明/7EB不変の4例、各基本/非連続の8区分、全monitor行を元出力と照合 | 固定模擬出力を画面で確認できる |
| 静的見本 | 390pxと広い画面で欠落・横はみ出しなし、見出し順、色なしでも状態と保留理由を識別、オフライン表示、外部要求なし | 見本の可読性とオフライン表示 |
| 動的接続 | 未取得/取得中/成功/拒否/例外、scope失効、dispose、接続/対象参照不一致で旧行が残らない | 模擬画面内の記録寿命を管理できる |
| 動的接続 | 取得中の閉じ直し/ロック/対象変更と遅着結果、連続操作、破棄後再表示を検証 | 古い模擬結果の混入を拒否できる |
| 実車接続 | 対象車両・ECU・transport適合、実取得元、前後の所有権、消去境界、復旧、実車試験を別途成立させる | 試験した対象と範囲だけ。模擬合格からの代用は禁止 |

今回変更するのはこの設計と開発記録だけ。原因候補順位、診断ロジック、保存schema、通常UI、read-only許可リスト、実行/送信フラグを変更しない。画面の実装完了や実車対応率へ換算しない。
